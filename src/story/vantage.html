01The problem

Agents can gather the evidence. They can't own the decision.

An AML alert is a question: is this activity suspicious? Answering it means pulling transactions from core banking, checking sanctions and PEP lists, reading adverse media and writing it up. Most of that is collection, and collection is what agents are good at. The rest is a regulatory problem: an agent that quietly fails, or a batch signed without looking.

02The rules

In compliance, a missing check that looks like a clear is worse than a slow one.

A regulator will always ask who decided.

Three rules framed every screen after that.

Agents gather and check; they never close, file or sign.The line is written on the inbox itself, so nobody has to remember it.
A failed agent shows no result at all.Never a partial score that could be read as an answer.
Speed comes from batching, not from skipping.Low-risk cases are signed together, only after reviewing a random sample.
03The key decision

When an agent fails, the case says so, and stops.

Risk and Regulatory start only when Context has the transactions. If Context fails, they wait instead of producing results on incomplete data, and the decision stays locked until all four agents finish.

What I chose
  • A fixed agent order: Context → Risk → Regulatory → Drafting.Every case reads the same way, and it's obvious why an agent is waiting.
  • Ask one question instead of guessing an entity match.One more step for the analyst; a wrong “same entity” would change the outcome.
  • A flagged sample pauses the whole batch.A rule that let one bad case through might be letting others through too.
What I discarded
  • Running all agents in parallelFaster on good days, and results built on incomplete data on bad ones.
  • A partial score when a source times outIt reads like a clear. Nothing at all is safer.
  • Signing pre-cleared cases in bulk, unseenFast, and it defeats the point of a person signing.
04What I built

Sign 62 cases at once, after checking three.

Most alerts are low risk and pre-cleared by a rule. Signing them one by one wastes the analyst's attention; signing them blind defeats the point. The batch flow asks for a random sample first, and one bad sample stops everything.
